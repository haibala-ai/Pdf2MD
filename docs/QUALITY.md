# 质量检查与识别边界

## 如何看检查结果

`quality.json` 的 `mechanical_checks_passed` 检查：

- 两份结构化 JSON 的页码完整、有序、无重复，并标记全文已解析。
- Markdown 非空。
- 正文、复核文档、原页索引引用的本地图片均存在。
- 英文原生文本适用时，词频重叠至少为 80%。

英文词数不足 100、中文为主或没有文本层时，词频指标为 `null`，要求人工复核。词频重叠不能衡量公式准确率、表格单元格准确性或阅读顺序。

检测到公式、算法、空结构页或指标不适用时，`quality_status` 为 `needs_review`。它可以和 `mechanical_checks_passed=true` 同时出现；转换退出码仍为 0。退出码 2 才表示结构检查未通过。

## 算法

默认按区域从 PDF 提取原生文字，并检查标题、编号步骤、异常字符和词汇重叠。满足条件且能完整映射到 Markdown 时，采用原生转写；否则保留 OCR。原始 Markdown、模型 JSON、两种转写及选择原因都保留。

原生文字能避免额外的识别错误。例如 PiPNN 的 Algorithm 2 中，OCR 将 `if` 读成 `\inf`，并在 `argmin` 下标附近生成伪影；原生文本能读出正确字符。本项目按算法块选择文本来源，没有全局替换合法的 `\inf`。

纯文本会展平部分上下标和缩进，不能视为可执行代码。算法的数学排版与控制流层级应以附带的 216 dpi 原图为准。扫描件没有可用文字层时会保留 OCR。

## 公式

`review.json` 枚举模型检测到的公式片段，包含 LaTeX、页码、区域和可疑标记。独立公式及可疑项在 `review.md` 中附原图；行内公式通常只保留了所在块的区域，不能将其当成精确的单公式边界。

规则覆盖括号/环境不配对、未知字符、算法中的 if/inf 冲突及部分 argmin 下标伪影。这些规则只建立复核队列，不能检出所有错误。所有公式的语义准确性均为 `unverified`；0 项标记也不意味着正确。清单计数不是作者论文中数学表达式的真实总数。

公式仍保留识别得到的 LaTeX，不自动猜测替换。在局部试验中，单纯从 144 dpi 提升至 288 dpi 并未消除过窄切块的问题，有时还产生新下标。扩大上下文有助于恢复 argmin 等内容，但混入算法引导线或箭头会污染识别。进一步提升应优先处理切块边界，再评估局部重识别。

## 验证范围

Windows 环境已验证两篇完整 PDF（18 / 23 页）、单页无文本层扫描件、Flash / Basic、模型校验、缓存复用及原页/区域图输出。22 项单元测试覆盖批次失败继续、同名隔离、旧产物保护、ZIP 越界防护、算法回退、原稿保留和公式规则。

Ubuntu 24.04 / WSL2（Python 3.12.3）已实际安装完整依赖及本地包，22 项单元测试、`pip check`、13 个模型文件的 SHA-256 校验均通过；并完成 Basic 单页扫描件和 Flash 18 页 PDF 的离线转换，结构检查通过。Windows 使用 Python 3.12.14 验证相同包布局与入口。

模型/软件版本固定不代表可以推导出所有 PDF 的准确率；遇到复杂公式、图表或算法应抽查原页。
